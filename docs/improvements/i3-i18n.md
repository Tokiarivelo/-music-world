# I3 — Every text in locale files, multi-language

## Goal

"No text may be static: all of it goes in locale files, multi-language." Every user-visible string (pages, buttons,
errors, aria labels, the VR panel, `<title>`, dates and numbers) comes from message files, with a language switch.

## Current state

- Strings live in `features/*/consts/*.consts.ts` (`UPLOAD_TEXT`, `PLAYER_TEXT`, `WORLD_VIEW_TEXT`, `AUTH_TEXT`,
  `DIRECTOR_TEXT`, `TEMPLATE_STORE_TEXT`): static English constants, plus literals in some components and in
  `app/layout.tsx` metadata (`lang="en"`).
- The API returns error codes and English messages; the web shows its own text for known codes.
- The VR panel uses a bundled **MSDF Inter font**: glyphs missing from the atlas render as boxes (pitfall in
  `docs/pitfalls.md`), so accented letters need checking before French or Malagasy appear in VR.
- Repository rule: code, comments and docs are English. **UI messages are data**, and `en` stays the source language.

## Requirements

1. ALL user-visible text SHALL come from message catalogs under `src/i18n/messages/<locale>/<namespace>.json`; no
   string literal in JSX, `aria-*`, `title`, `placeholder`, metadata, toasts, VR panel or error mapping.
2. LOCALES: `en` (source), `fr`, `mg` (Malagasy) at first; adding one = a folder of JSON files + one registry line.
3. THE locale SHALL be chosen by: explicit user choice (cookie `mw_locale`, 1 year) > `Accept-Language` > `en`.
   `<html lang>` and `dir` follow it; the choice survives navigation and reload.
4. A language switch (select in the nav, keyboard accessible, labelled in its own language) SHALL change the language
   without reloading the world or interrupting the audio.
5. Messages SHALL support parameters and plurals (ICU style: `{count, plural, one {# note} other {# notes}}`) and
   locale-aware dates, numbers and durations through `Intl`.
6. KEYS SHALL be typed: a missing key or a missing parameter is a TypeScript error; a missing translation falls back
   to `en` at run time and fails a test.
7. A test SHALL fail when two catalogs have different keys or parameters, and a lint rule (`react/jsx-no-literals` or an
   equivalent test scanning `.tsx`) SHALL fail on raw text in JSX.
8. THE VR panel SHALL render every supported language without missing glyphs (atlas regenerated with Latin-1
   Supplement + Latin Extended-A at least).
9. API errors SHALL stay codes (`TEMPLATE_INVALID`…); the web maps each code to a catalog key. The API never needs a
   locale; unknown codes show a generic localized message.
10. LLM prompts, schema, logs and docs stay English. Lyrics are shown as transcribed (not translated).

## Design

- Library choice (decision, recommended: **`next-intl`** if it supports the Next 16 App Router with cookie-based
  locales and no URL prefix; otherwise a ~120-line in-house provider). Evaluate both in task 1 against: bundle size
  (< 15 KB), typed keys, client + server components, MIT licence.
- No URL prefix (`/fr/...`): routes, `/play/demo` and shared links stay unchanged.
- `I18nProvider` (client) receives the locale and the catalogs of the current page's namespaces from the server layout;
  `useT(namespace)` returns `t(key, params)`; `getT` for server components and metadata (`generateMetadata`).
- Namespaces = features (`common`, `upload`, `player`, `world`, `auth`, `store`, `director`, `xr`, `errors`), loaded
  per route to keep bundles small.
- XR: panel strings are passed from the React side to the world host as a resolved dictionary (the engine stays
  framework-free); changing language updates the panel text through `WorldHandle`.
- Migration is mechanical: each `*_TEXT` constant becomes a namespace JSON, the component calls `t('key')`.

## Tasks (one commit each)

1. Evaluate and pick the library; ADR in `docs/decisions/` (rules: documentation.md).
2. Provider, `useT`, `getT`, locale resolution (cookie, header), `<html lang>`, language switch, typed keys; tests.
3. Catalog tests (parity of keys and parameters) and the JSX-literal lint rule, initially with an allowlist.
4. Migrate `common` + `world-view` + `player` (+ the nav of I1); remove the constants.
5. Migrate `upload`, `auth`, `director`, `template-store`; metadata and error mapping; remove the allowlist.
6. XR panel: dictionary injection, glyph atlas for Latin extended, panel test with French strings (no tofu).
7. Translations: `fr` and `mg` (draft by the agent, **review by a native speaker**); `es` etc. later.
8. Docs: README (adding a language), `frontend.md` rule "no literal text", `PROJECT.md` §7, handoff.

## Verification

Vitest (catalog parity, `t` with plurals), Testing Library with the provider in two locales, Playwright screenshots in
`fr` and `mg` (long words must not overflow), xr-check with a French panel, switch language while playing.

## Risks and decisions

- Text expansion (French ≈ +30 %): layouts use wrapping, no fixed widths on buttons.
- Malagasy translations need a human reviewer; mark machine drafts in the file header until reviewed.
- Effort grows with the number of strings: ≈ 150–200 today; later phases add more, so do I3 first.
